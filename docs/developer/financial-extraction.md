# Open-field financial extraction

**Status (2026-10-06): bounded concurrent extraction and checked short references are integrated.** The historical v2 rerun processed 3 filings (46 original windows) with 100% provider/schema completion, 97.79% record validity and 97.23% numeric validity. These are local-contract checks, not financial accuracy or recall: 163 split-parenthesis negative amounts remained text. Version v3 retains strict checks and adds exact checked-short-ref decoding. The async queue defaults to 4 local-processing workers, 1 model worker and a 4-window prefetch; final results preserve source order.

## Workflow and ownership

The source-neutral `financial_extraction` package owns evidence construction, request formation, model protocol, source-grounded validation, and a durable journal under an explicit work directory. `filings` owns archive identity, filing selection, archive integrity checks, and source-byte binding. The host command requires explicit filing IDs and accepts at most 50; it does not promote candidates or replenish failures. Window extraction runs as an async bounded queue (`run_extraction_async`, with a synchronous `run_extraction` wrapper) in stable source order and no automatic retries. A producer plans windows into a queue bounded by `prefetch_windows`; `model_workers` consumers admit and send provider calls while `workers` local slots validate responses and run completion callbacks. Results remain outside the archive and are never published.

The open record schema preserves original `source_label`, inferred `name` and `category`, string value, value type, source quotes, optional unit/currency/scale, period and arbitrary dimensions. Names and categories are not constrained to a predefined metric registry. The host's original filing identity and the archive remain authoritative.

## Safety and runtime

`build_evidence` parses verified HTML without network access. `iter_windows` covers every evidence block and cell as core exactly once; headers may repeat as context. Structural boundaries must not concatenate neighboring digits. A request is rejected rather than truncated when the final serialized request exceeds `max_request_bytes`.

The OpenAI-compatible client loads the SDK lazily and requires an explicit API key loaded from `[secrets].api_key` in `secrets.toml`. It never reads environment variables. Credentials are excluded from config/client repr, descriptors, request identity and request journals; SDK error messages redact the active key. Automatic retries remain disabled; refusal, empty content, and incomplete responses are errors, and validation failures are never auto-corrected or retried. `provider.structured_mode` selects `json_schema` (default, strict server-side schema) or `json_object` (valid JSON object mode). In `json_object` mode the request includes the schema and an example in its system prompt; responses are still strictly parsed and validated locally. DeepSeek uses `response_format={"type":"json_object"}`. The prompt must match numeric multipliers and the original value lexemes. Application-side cost…

The durable journal stores exact requests and responses. A pending request with no response is treated as unknown and is not automatically resubmitted: `RequestStateError` (unknown prior state or request-identity collision) fails only that window while extraction continues, whereas other journal failures (corrupt journal, stored-response hash mismatch, unwritable journal) are fatal `StoreError` and stop admission of new sends. A duplicate identical window in the same batch waits for the first window's journal write, then replays the persisted response with a single provider call. Unknown-outcome transport failures (`UnknownRequestError`: timeouts and connection errors, with the key redacted) likewise stop admission of new sends; the failing window is recorded as submitted, already-running calls run to return or timeout, and other provider errors fail only their window. The host CLI verifies the selected archive snapshot and source refs, writes only to an explicitly supplied work directory, and reports `publishable: false`.

Prompt revision `open-financial-v3` preserves the explicit numeric contract from v2: numeric `value` retains its source lexical token (separators, signs and permitted affixes); `scale` is null or a positive decimal multiplier string such as `"1000000"`, never `"millions"`. Every non-text value names a configured numeric policy; all policy sign/affix options are supplied. Quotes remain exact contiguous substrings of refs in the current window. Unsupported lexical forms remain text facts; no automatic normalization or retry conceals failed validation. Four executors isolate the stages: a single-thread prepare executor, a model executor with `model_workers` threads, a single-thread journal executor that performs every journal write, and a processing executor with `workers` threads for validation and synchronous completion callbacks. The provider client reuses one lazily built SDK handle across concurrent `complete` calls (construction guarded by a lock) and is closed after the run through its context manager; custom clients must support concurrent `complete` calls up to `model_workers`, or run with `model_workers=1`. `on_window_complete` receives each finished `WindowOutcome` and may be a plain function or an async callable; callback failures are logged and never change the recorded outcome or retrigger work. A slow validation or callback holds a local-processing slot but never a model slot, so later provider calls still start.

Model-facing evidence uses deterministic, window-local short refs: `r` plus six hexadecimal index digits and two modulo-17 check characters. The checks detect any single-character substitution and an adjacent swap of different index digits; they do not establish correct source attribution or protect against all multi-character errors. Core/context duplicates share an ID. The exact short→original mapping is recorded in the request journal and included in request identity, but is not sent as provider metadata. Every quote field is decoded through that request's mapping before validation against the original evidence. Unknown IDs, shortened IDs, original long IDs and typos stay unresolved; there is no prefix matching, edit-distance repair or quote-search fallback. Raw model responses remain unchanged; final refs and source locations use original evidence identities. The protocol change gives new request identities, so old long-ref requests are not reused as short-ref requests.

A targeted private comparison on the same Microsoft windows 5, 12 and 14 improved record validation from 54/163 to 164/165 and numeric validation from 52/161 to 161/162. All three stopped and passed schema checks; scale, lexical-presence and missing-policy problems disappeared, with one label quote mismatch remaining. This selected failure sample does not establish accuracy or recall. The comparison used three concurrent workers and a 110KB request cap to retain the old evidence boundaries despite the longer prompt (local default remains 100KB); normal planning includes prompt bytes in its cap. Results: `/tmp/opencode/deepseek-prompt-v2-5t7geqp5/assessment.json`.

The fresh 20-company/20-10-K v3 batch planned and attempted 598 windows through the real CLI. Only 243 returned `stop`; 240 passed local schema parsing. Failures were 331 HTTP 402 insufficient-balance errors, 23 HTTP 429 concurrency-limit errors, one `length` and three schema errors. The provider explicitly lowered its allowed concurrency as balance declined; no retries were made. The 21,394 returned schema-valid records had 20,812 valid records and 16,204/16,750 valid numeric records, but these survivor-only rates omit 358 failed windows. All refs in the 240 schema-valid responses belonged to their exact short-ref maps; this does not establish correct attribution between repeated quotes. Another 1,352 open-parenthesis numeric fragments remained text. Evidence: `/tmp/opencode/new20-shortrefs-20261006/model-shortrefs/assessment.json`; failed-window index and raw responses are retained. Completing the batch requires funded provider access and explicit rerun authorization; do not blindly resubmit pending journal identities.

## Limitations and pilot gate

Citation and schema validation do not establish financial correctness or completeness. Numeric values require an explicit `NumericPolicy`; unparseable numeric outputs remain unresolved, while values explicitly returned as text do not undergo numeric parsing. Amounts with parentheses split across HTML cells may therefore be text-valid without numerical coverage. The two historical pilot archives had only 3 bind-eligible filings under the primary-document gate. A separately authorized fresh batch of 20 previously unprocessed 10-Ks has now been frozen and acquired in its own archive; this is not a 50-filing run. Do not relax eligibility or replace model failures. The private 100K-output configuration uses a 600-second timeout. `model_workers` bounds concurrent provider calls (default 1), not total token cost; rate limits can fail individual windows without retry. Cancellation cancels queued calls but waits for already running calls to return or time out.

## Commands

The supported local entry point is:

```bash
quant-dataset filings extract-financials \
  --archive PATH --work-dir PRIVATE_PATH --config config/extraction.toml \
  --filing-id FROZEN_ID
```

Repeat `--filing-id` for the frozen list, up to 50 unique IDs. Configure `config/extraction.toml` from the example; the CLI sends selected source contents to that provider, writes a non-publishable result and journal outside the archive, and never publishes.
The CLI sends progress to stderr and keeps its final JSON summary on stdout. It reports filing preparation and completed/total windows (the total is unknown until evidence generation is exhausted), queued windows, in-flight provider requests, durably saved responses, replayed windows, failed windows, unresolved records, and the result-writing phase. `--no-progress` disables live reporting. `saved` counts journaled complete responses and can exceed validated windows, because a saved response may still fail local validation; completed windows include failures. Progress events are transient and never enter request identity, the durable journal, or `result.json`.
## Configuration

Copy `config/extraction.example.toml` to `config/extraction.toml` for the base URL, model and `structured_mode`; use `json_object` for DeepSeek and `json_schema` for providers supporting strict JSON Schema. Store the key only in `[secrets].api_key` of the gitignored `config/secrets.toml`. The CLI defaults to that path and accepts `--secrets PATH`; direct `load_extraction_config` calls default to `secrets.toml` beside the extraction config. Missing, empty or placeholder keys fail closed even if environment variables are set. `provider.api_key` and `provider.api_key_env` are rejected; there is no legacy fallback. Keep the existing SEC/FRED fields in `[secrets]` unchanged. Never share or commit private secrets or put real keys in examples. Set `[extraction].workers` (local validation/processing slots, default 4), `[extraction].model_workers` (concurrent provider calls, default 1) and `[extraction].prefetch_windows` (bounded planned-window queue, default 4) to positive integers with `model_workers` not exceeding `workers` or `prefetch_windows`; violations fail closed. The CLI `--workers`, `--model-workers` and `--prefetch-windows` flags override the configured values. Bound provider overlap against service rate limits. Numeric values are normalized only under an explicitly configured policy; never guess locale formats from filing content.

The CLI loads provider and policy settings, prepares, extracts through the bounded async queue, validates citations, and writes the request journal plus complete non-publishable `result.json` to `--work-dir`. It does not modify or publish the archive.

```bash
quant-dataset filings extract-financials \
  --archive PATH --work-dir PRIVATE_PATH --config config/extraction.toml \
  --filing-id FROZEN_ID
```

Repeat `--filing-id` for the frozen list, up to 50 unique IDs. Confirm every ID is already eligible before starting; failed IDs are not replaced or replenished.

## Async queue API and migration

Library callers use the coroutine `run_extraction_async(documents, *, client, task, limits, work_dir, protected_paths=(), workers=4, model_workers=1, prefetch_windows=4, on_progress=None, on_window_complete=None)` in `financial_extraction.workflow.runner`; `run_extraction` accepts the same arguments and runs the queue to completion synchronously, and is also re-exported from `financial_extraction.workflow`. `on_progress` is the existing synchronous progress callback; `on_window_complete` receives each finished `WindowOutcome` and may be sync or async. The filings host `extract_selected_filings` forwards the same `workers` / `model_workers` / `prefetch_windows` / `on_progress` / `on_window_complete` knobs.

Previously `workers` (default 32) bounded provider overlap. That overlap is now `model_workers` (default 1): to restore N-way provider concurrency, set `model_workers=N` with `workers>=N` and `prefetch_windows>=N`. Keep `model_workers=1` unless the provider allowance and the client support concurrent calls. Old TOML files that set only `workers` keep loading; unset fields take the new defaults.
